# Garmin Project

A Python/Jupyter workspace for analysis and notebook development.

## Setup

```bash
python -m pip install -r requirements.txt
python -m ipykernel install --user --name garmin-project
```

## Sync Garmin data to Supabase

1. Run `schema.sql` once in the Supabase SQL Editor.
2. Set `SUPABASE_DB_URL` in `.env` to the connection string from Supabase Database Settings.
3. Ensure Garmin tokens are available in `GARMINTOKENS`, or provide `GARMIN_EMAIL` and `GARMIN_PASSWORD`.
4. Run the sync from this project folder:

```bash
python sync_garmin_to_supabase.py --days 7
```

The sync upserts daily summaries, activities, sport totals, and raw API payloads. It skips finalized historical dates, refreshes today on every run while the day is in progress, and finalizes yesterday once. The `daily_summaries.is_final` marker prevents repeated fetching of completed days.

If the direct database hostname is unreachable, use the Supabase pooler connection string from Database Settings instead.

## GitHub Pages report

The text-only report is generated by `build_report.py` from Supabase data. The GitHub Actions workflow in `.github/workflows/pages.yml` runs daily and can also be started manually.

For the workflow, add these GitHub repository secrets: `SUPABASE_DB_URL`, `GARMINTOKENS_MANGA_B64`, and `GARMINTOKENS_CHIPS_B64`. These are Base64-encoded contents of each account's local `garmin_tokens.json`. Password login is intentionally disabled in the sync script. Do not commit `.env` or token files. The report stores both accounts separately and provides a manga/chips toggle.

GitHub Pages visibility is controlled by GitHub organization and repository settings. A private repository does not automatically make a Pages site private on every GitHub plan, so check the Pages visibility setting before publishing personal health data.
